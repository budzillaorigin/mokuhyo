### D-001: Repo root is the existing project folder (2026-09-18)
The brief's quick start assumes a fresh `tsumugi/` folder. The owner's existing folder (`Japanese Learning App/`) is the repo root instead, and `KOTOBA_UNIFIED_APP_BRIEF.md` was renamed to `BRIEF.md`. Nothing depends on the folder name.

### D-002: Toolchain versions (2026-09-18)
Kotlin **2.4.10**, AGP **9.4.0**, Gradle **9.7.1**, JDK 21, compileSdk **37**, targetSdk 36, minSdk 26. Kotlin is pinned one patch behind latest (2.4.20) because SKIE 0.10.14 only supports up to 2.4.10. compileSdk 37 is required by the current AndroidX Compose and OkHttp releases. When upgrading Kotlin, check SKIE's supported-version list first; the build fails fast with a clear message if they mismatch.

### D-003: Android KMP target uses `com.android.kotlin.multiplatform.library` (2026-09-18)
This is AGP 9's supported way to add an Android target to a KMP module; the old `com.android.library` + KMP combination is deprecated. Shared `commonTest` runs as Android host (JVM) tests via `withHostTest {}`. It also runs on the iOS simulator on macOS.

### D-004: iOS consumes the shared framework via direct integration, not SPM (2026-09-18)
BRIEF.md §3.3 says "local SPM package produced by `embedAndSignAppleFrameworkForXcode`", but that Gradle task is the *direct* (run-script) integration and doesn't produce an SPM package. We use direct integration: a run-script phase calls the task, and `FRAMEWORK_SEARCH_PATHS` / `-framework Shared` link the static `Shared.framework`. It's the path JetBrains and SKIE document best. Revisit if we later need a binary XCFramework for extensions (widgets, share sheet), which would be via `assembleSharedXCFramework` + a local SPM binary target.

### D-005: Xcode project written by hand with synchronized folders (2026-09-18)
Development happens on Windows, so the project couldn't be generated by Xcode. `project.pbxproj` uses Xcode 16's `PBXFileSystemSynchronizedRootGroup`, so every file under `iosApp/Tsumugi/` and `iosApp/TsumugiTests/` is picked up automatically with no per-file entries. Requires **Xcode 16+**.

### D-006: Swift 5 language mode with complete concurrency checking, for now (2026-09-18)
CLAUDE.md asks for "Swift 5.10+/6 with strict concurrency". The project starts with `SWIFT_VERSION = 5.0` + `SWIFT_STRICT_CONCURRENCY = complete`, so concurrency problems show up as warnings rather than errors. The first iOS build can't be run from the Windows dev machine, and this keeps it from failing on Kotlin-bridged types. Switch to `SWIFT_VERSION = 6.0` once the project compiles warning-free on a Mac.

### D-007: Dev machine is Windows 11 ARM64 (2026-09-18)
JDK (Temurin 21, `~/.jdks`) and Android SDK (`%LOCALAPPDATA%\Android\Sdk`) were installed per-user. Kotlin/Native can't compile iOS targets on Windows, so iOS is verified by the macOS CI job and on the owner's Mac. `kotlin.native.ignoreDisabledTargets=true` keeps the Windows build quiet about that.
